# AI 유지보수 정책

이 정책의 목적은 ERP PoC에서 AI가 변경 후보를 정리하되, 업무 규칙이나 운영 환경을 독자적으로 바꾸지 못하게 하는 것입니다.

## 기본 원칙

- AI는 신호 수집, 후보 정리, 보고서 생성까지만 자동으로 수행합니다.
- `finalDecision`은 항상 비워 둡니다. 사용자가 `APPLY`, `HOLD`, `REJECT`, `NEEDS-BUSINESS-DECISION` 중 하나를 결정합니다.
- AI는 merge, push, 배포, 운영환경 접근, DB·SQL 변경을 수행하지 않습니다.
- 동결 시각 이후에는 신호와 보고서만 만들고, 사전개발 브랜치나 코드 수정은 만들지 않습니다.

## 후보 등급

| 등급 | 대상 | 사전개발 |
| --- | --- | --- |
| Green | 테스트, 문서, 단순 UI 문구·레이아웃, 중복 클릭 방지, 복구 상태, 안전한 진단 스크립트 | 허용 가능 |
| Yellow | 공통 컴포넌트, 다중 화면 리팩터링, API 클라이언트, 성능, 예외 처리 구조 | 사용자 확인 후 검토 |
| Red | 업무 규칙, 금액·수량, 상태 전이, 인증, API·DTO, DB·SQL, 고객사 로직, 생산·재고·검사, MES·PLC, 운영·배포 | 금지 |

## 실행 경계

`scripts/qa/verify-maintenance-boundaries.mjs`는 다음 상태를 차단합니다.

- `main` 또는 `master` 브랜치에서 사전개발 시도
- dirty working tree에서 사전개발 시도
- 보호 경로(API, DTO, DB, SQL) 변경
- 동결 상태 또는 ACTIVE가 아닌 정책 상태에서의 사전개발
- Red 후보 사전개발
- merge·배포 계열 명령 또는 민감정보가 포함된 입력

차단은 오류를 숨기지 않습니다. 어떤 정책 범주가 멈췄는지만 출력하며, 비밀 값이나 파일 내용은 출력하지 않습니다.
