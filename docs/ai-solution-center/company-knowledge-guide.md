# 회사 지식팩 작성 가이드 (관문 12-2)

## 목적과 적용 범위

회사 지식팩은 컨설턴트 파일 분석과 고객 업무 Q&A의 추천 근거를 보완하는 JSON 형식의 로컬 PoC 자료입니다. 현재 버전은 선택한 브라우저 세션의 메모리에서만 사용하며 서버·DB·외부 AI로 전송하지 않습니다.

이 파일을 불러온다고 해서 회사 업무 규칙이 확정되는 것은 아닙니다. 실제 적용 전에는 컨설턴트의 업무 검토와 개발 담당자의 기술 영향 검토가 필요합니다.

## JSON schema

최상위 값은 배열이며, 각 항목은 아래 허용 필드를 모두 포함해야 합니다. `sourceType`, `companySpecific`은 사용자가 입력하지 않으며, 검증 후 각각 `COMPANY`, `true`로 자동 부여됩니다.

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `id` | 문자열 | 지식 항목 식별자 |
| `title` | 문자열 | 화면에 표시할 제목 |
| `category` | 문자열 | 자재, 공정, 검사 등 업무 분류 |
| `keywords` | 문자열 배열 | 입력과 일치 여부를 찾는 핵심 단어 |
| `symptoms` | 문자열 배열 | 현재 나타나는 업무 증상 |
| `recommendations` | 문자열 배열 | 기본 검토 권고안 |
| `alternatives` | 문자열 배열 | 대안 또는 단계적 적용 방식 |
| `requiredInformation` | 문자열 배열 | 적용 전 확인할 정보 |
| `risks` | 문자열 배열 | 위험과 주의사항 |
| `applicableProcesses` | 문자열 배열 | 적용 가능한 업무 단계 |
| `confidenceWeight` | 숫자 | 0 이상 1 이하의 참고 가중치 |

필수 문자열은 비어 있을 수 없고, 모든 배열도 최소 한 항목을 가져야 합니다. 허용하지 않는 필드와 `finalDecision`, `riskLevel`, `executableCode`, `prompt`, `systemPrompt`, `html`, `script`는 차단됩니다.

## 제한과 샘플

- 파일: `.json` 또는 `application/json`, 1개, UTF-8, 최대 256KB
- 항목: 최대 100개
- 길이: `id` 100자, `title` 200자, `category` 100자, 키워드 하나 100자, 그 외 배열 문장 하나 1,000자
- 배열: 필드별 최대 30개

[company-knowledge-sample.json](company-knowledge-sample.json)은 민감정보가 없는 PoC 예시입니다. 실제 회사 확정 규칙이 아닙니다.

## 작성·검토 절차

1. 업무 자료를 수집하고 개인정보·고객정보·비밀번호·재무정보를 제거합니다.
2. 컨설턴트가 업무 증상, 권고안, 현장 적용 가능성을 검토합니다.
3. JSON 구조와 제한을 지켜 지식 항목을 작성합니다.
4. 개발 담당자가 기존 ERP 메뉴·테이블·API, 데이터 흐름, 인터페이스, 성능·예외 처리 영향을 확인합니다.
5. 질문과 기대 근거를 포함한 테스트를 작성해 테스트 환경에서 불러옵니다.
6. 검토 승인과 변경 이력을 남긴 뒤 해당 환경에 반영합니다.
7. 정기적으로 최신 업무 기준과 충돌 여부를 재검토합니다.

회사 지식은 일반 ERP·MES 지식과 구분되어 결과의 근거에 표시됩니다. 회사 지식이 일치하더라도 확인 질문과 외부·내부 검토 필요 표시는 유지합니다.

## 배포 전 확인

- 민감정보와 고객 식별 정보가 없는가
- JSON schema와 길이 제한을 통과하는가
- 컨설턴트 업무 검토와 개발 영향 검토가 완료됐는가
- 정상·형식 오류·schema 오류·초기화 시나리오를 테스트했는가
- 현재 PoC가 브라우저 세션 메모리에서만 적용됨을 이해했는가
