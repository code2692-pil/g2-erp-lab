# AI 솔루션 검토 패키지 가이드

## 목적

AI 솔루션 센터의 추천 결과를 컨설턴트·개발·현장 담당자가 검토할 수 있도록, 안전한 요약 정보와 판단 기록을 JSON으로 교환하는 로컬 PoC 기능입니다.

이 패키지는 실제 승인, 전자결재, 사용자 인증, 권한 관리 또는 적용 완료를 뜻하지 않습니다.

## 형식과 버전

최상위 구조는 아래와 같습니다.

```json
{
  "packageType": "AI_SOLUTION_REVIEW_PACKAGE",
  "schemaVersion": "1.1",
  "case": {}
}
```

새로 다운로드하는 패키지는 `1.1`입니다. 기존 `1.0` 샘플과 사용자가 보관한 `1.0` 패키지도 계속 불러올 수 있습니다. 알 수 없는 상위 버전, 허용하지 않은 field, 실행 가능한 내용은 전체 패키지를 거부합니다.

## 상태

- `PENDING`: 아직 담당자 판단이 기록되지 않은 상태
- `APPLY`: 현재 추천안을 적용 전제로 검토하는 상태
- `HOLD`: 정보 부족 또는 우선순위 이유로 보류한 상태
- `REJECT`: 현재 추천안을 적용하지 않기로 한 상태
- `NEEDS_BUSINESS_DECISION`: 업무 책임자·고객·현장 책임자의 기준 결정이 필요한 상태

`APPLY`에는 검토자 역할과 하나 이상의 체크리스트 확인이 필요합니다. `HOLD`, `REJECT`, `NEEDS_BUSINESS_DECISION`에는 사유가 필요합니다.

## 검토자와 체크리스트

검토자 역할은 컨설턴트, 개발 담당자, 현장 담당자, 고객 담당자 중 하나입니다. 표시명은 선택 사항이며 실제 계정이나 전자 서명을 의미하지 않습니다.

체크리스트는 컨설턴트, 개발, 현장 확인 항목을 기록할 뿐 업무 규칙을 자동으로 확정하지 않습니다.

## 포함 정보

- 분석 유형·차수·감지 업무영역·안전한 입력 요약
- 추천 1·2순위, 우선순위 점수, 로드맵 요약
- 미해결 항목, 지식 근거의 제목·분류·일치 키워드
- 입력 근거의 출처명과 최대 300자 발췌
- 파일 처리 건수·포함/제외/차단 건수, 안전한 파일 유형·구조·내용 요약
- 적용한 실전 시나리오와 관련 부서·우선순위 요약
- 검토 상태, 역할, 의견, 사유, 체크리스트, 제한사항

## 제외 정보와 주의

패키지는 파일 바이너리, 실제 파일명, 전체 파일 본문, 파일별 메모 전체, 고객 문의·후속 답변 전체, 회사 지식팩 전체, 절대 경로, 비밀번호, 토큰, secret, 실행 가능한 script, HTML을 포함하지 않습니다. 파일은 `첨부 N (유형)`과 집계·마스킹된 요약만 포함합니다.

이메일·전화번호·IP·주민등록번호 후보·카드번호 후보·URL query token·password/access/refresh/API/secret/Bearer/AWS key·긴 토큰 후보는 마스킹합니다. 자동 탐지는 보조 장치이므로 개인정보·고객 정보·회사 기밀 정보는 원본 입력 단계에서부터 제외해야 합니다.

## 다운로드와 불러오기

검토 기록을 만든 뒤 **검토 패키지 다운로드**를 선택하면 `ai-solution-review-{timestamp}.json` 형식의 파일을 만듭니다. 파일명에는 고객명, 사용자명, 파일명, 질문 내용, 검토자 표시명이 들어가지 않습니다.

**검토 패키지 확인**에서는 UTF-8 JSON 한 개만 읽습니다. 확장자 또는 MIME type은 JSON이어야 하며 최대 256KB입니다. `1.0`과 `1.1`만 허용하며 schema가 맞지 않거나 위험 field가 있으면 기존에 불러온 패키지를 유지한 채 전체 거부합니다.

불러온 패키지는 현재 분석 입력·추천 결과를 자동으로 바꾸지 않는 별도의 검토 요약입니다.

## 실제 회사 적용 전 필요 사항

실제 회사 적용에는 별도의 사용자 인증·권한·전자결재·DB 저장·감사 로그·보안 검토가 필요합니다. 현재 기능은 이들을 대체하지 않는 브라우저 메모리 기반 PoC입니다.
