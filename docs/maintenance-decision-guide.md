# 유지보수 후보 결정 안내

보고서의 후보는 작업 지시가 아니라 검토 대기열입니다. 각 후보의 `finalDecision`은 사용자가 결정합니다.

| 결정 | 사용할 때 | 다음 행동 |
| --- | --- | --- |
| `APPLY` | 사용자 영향과 검증 범위가 명확할 때 | 별도 작업 지시로 구현 범위를 확정 |
| `HOLD` | 더 많은 로그·사용자 확인이 필요할 때 | 신호만 다시 수집 |
| `REJECT` | 현재 우선순위와 맞지 않을 때 | 후보를 종료 |
| `NEEDS-BUSINESS-DECISION` | 업무 규칙, 금액, 수량, 상태 전이가 얽힐 때 | 업무 책임자가 기준을 결정 |

검토 순서:

1. `userVisible`에서 사용자가 실제로 느끼는 영향을 확인합니다.
2. `risks`와 `effect`로 화면·API·DB 영향 범위를 확인합니다.
3. Green인지, Yellow/Red인지 확인합니다.
4. `verification`이 가능한지 확인한 뒤에만 `APPLY`를 선택합니다.

Red 후보는 자동 사전개발 대상이 아닙니다. API·DTO·DB·SQL·운영 설정을 포함하면 업무 결정과 별도 승인 없이는 진행하지 않습니다.
