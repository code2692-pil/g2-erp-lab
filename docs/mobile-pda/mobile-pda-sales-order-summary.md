# 모바일·PDA 수주등록 PoC 요약

## 목적

- 모바일 수주등록은 스마트폰 세로 화면에서 기존 수주를 카드로 조회하고 입력·수정하기 위한 브라우저 기반 PoC다.
- PDA 수주등록은 산업용 소형 단말의 키보드 입력 흐름을 가정해 품목코드 → 수량 → 단가를 Enter로 연속 입력하는 브라우저 기반 PoC다.
- 두 화면은 PC 수주등록을 대체하는 별도 시스템이 아니라 같은 ERP 수주 업무를 화면 크기와 입력 방식에 맞게 표현한 것이다.

## 같은 데이터 사용 구조

```text
PC 수주등록 ─┐
모바일 수주등록 ├─ 동일 수주 API ─ 동일 Repository ─ 동일 수주 데이터
PDA 수주등록 ─┘
```

- API 모드에서는 세 화면 모두 기존 `/api/sales-orders` 조회·생성·수정·삭제 endpoint와 기존 DTO를 사용한다.
- Mock 모드에서는 기존 수주 Mock 원본을 감싸는 공통 데이터 서비스 인스턴스 하나를 세 화면이 공유한다.
- 모바일·PDA 전용 저장소, 데이터 복사, 동기화 명령, 화면별 별도 Mock 데이터는 없다.
- 실제 SQL Server 모드에서는 기존 PC 화면과 마찬가지로 서버 Repository를 통해 `SAL_SOH`, `SAL_SOL` 수주 원본을 사용한다.

## 화면별 UI 차이

| 화면 | 중심 UI | 입력 방식 |
| --- | --- | --- |
| PC | Header·Line Grid | 마우스와 키보드 대량 입력 |
| 모바일 | 수주·품목 카드 | 터치와 소프트웨어 키보드 |
| PDA | 압축 목록과 빠른 입력 | 품목코드·수량·단가 Enter 흐름 |

세 화면은 기존 수주 타입, 금액 계산, 입력 검증, 거래처·품목 데이터와 저장 API를 재사용한다.

## PoC 한계

- 네이티브 Android·iOS 앱이나 APK가 아니다.
- 실제 PDA SDK, 바코드 스캐너, 카메라, 블루투스 장비를 연결하지 않는다.
- 오프라인 저장, PWA, Service Worker를 지원하지 않는다.
- 실장비의 키 배열, 스캐너 suffix, 화면 밝기·장갑 조작성은 향후 실제 장비에서 검증해야 한다.
