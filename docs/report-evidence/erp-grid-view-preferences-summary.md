# ERP Grid 보기 설정 저장 — 관문 12-13 검증 요약

## 목적

수주·발주·작업지시의 PC 상세 Grid에서 사용자가 필요한 열만 보고, 업무 흐름에 맞는 순서로 볼 수 있도록 했다. 설정은 문서 입력값과 분리되어 브라우저에만 저장된다.

## 적용 범위

| 화면 | Grid ID | 고정 열 |
| --- | --- | --- |
| 수주등록 상세 | `sales-order-lines` | 라인 |
| 발주등록 상세 | `purchase-order-lines` | 라인 |
| 작업지시 공정상세 | `work-order-lines` | 공정순번 |

각 Grid는 독립된 설정 키를 사용한다. 헤더 Grid, 조회 조건, 모바일·PDA, AI 화면에는 적용하지 않았다.

## 사용자 동작

1. 상세 Grid의 **보기 설정**을 누른다.
2. 열을 표시/숨김하고 위·아래로 이동한 뒤 **적용**한다.
3. **취소**는 적용 전 초안을 버린다.
4. **기본값으로 초기화**는 확인 후 현재 Grid 설정만 제거한다. 문서 행과 입력값은 유지된다.

고정 열은 숨기거나 이동할 수 없으며 Dialog에 고정 상태와 이유를 표시한다.

## 데이터와 안정성

- 저장 항목: schema version, Grid ID, 열 ID, 표시 여부, 순서.
- 저장하지 않는 항목: 수주/발주/작업지시 번호, 거래처, 품목, 수량, 단가, 금액 등 업무 데이터.
- `localStorage` 파싱 오류, 구 schema, 다른 Grid 값, 삭제/추가/중복 열, 잘못된 순서는 안전한 기본값으로 정규화한다.
- 브라우저 저장 권한·용량 오류가 나도 화면 설정은 현재 세션에 적용되고 런타임 오류를 내지 않는다.
- 보기 설정만으로 문서의 `수정됨` 상태는 바뀌지 않는다.
- 필수값 오류가 숨긴 열에 있으면 해당 열을 다시 표시해 오류 위치를 잃지 않는다.

## Grid 생산성 연계

적용된 표시 순서는 헤더와 DOM 순서, Enter/Tab의 편집 포커스 순서에 동일하게 반영된다. 숨긴 열은 포커스 대상에서 제외된다. 붙여넣기는 현재 보이는 열 순서를 기준으로 동작한다.

## 검증 근거

- Grid 보기 설정 단위 테스트: 14/14 통과.
- Mock 브라우저 E2E: 6/6 통과 — 저장·새로고침 복원, 순서/Tab, 화면 간 분리, 초기화, 손상값·검증 열 복원, 1920/1440/1366/1280px.
- InMemory API: 수주·발주 API 시나리오 11/11 통과, 작업지시 생성·lookup 시나리오 단독 통과. 작업지시 전체 묶음 실행의 한 사례는 assertion 실패 없이 Playwright 비디오 컨텍스트 종료가 30초를 넘긴 환경 timeout으로 별도 기록했다.
- .NET 솔루션 빌드: 경고 0, 오류 0.

## 한계와 다음 기준

설정은 브라우저·기기별 localStorage에만 저장되며 로그인 계정 동기화나 서버 저장은 하지 않는다. 열 너비 조절 기능은 기존 Grid에 없으므로 포함하지 않았다. 모바일·PDA는 기존 동작을 유지한다.
