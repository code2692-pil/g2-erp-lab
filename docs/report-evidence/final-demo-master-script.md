# 최종 데모 마스터 스크립트 (7~10분)

## 데모 전 준비

- Mock 모드로 시작한다. SQL Server는 데모용이 아니라 별도 로컬 교차 검증 근거로만 언급한다.
- 브라우저 zoom은 100%로 둔다.
- 오류·확인 dialog가 이미 열려 있으면 취소 후 처음 화면에서 시작한다.

## 진행 순서

1. **개발환경 소개 (30초)**
   - 화면: PC 수주등록 첫 화면
   - 설명: “세 ERP 화면의 사용성, 검증, 요청 안정화를 개발환경 PoC로 직접 확인한 결과입니다.”

2. **PC 수주 조회와 Grid (50초)**
   - 조회를 누르고 Header와 Line을 선택한다.
   - 거래처/품목 Lookup, 수량·단가 변경과 합계, Enter/Tab 흐름을 보여 준다.
   - 기대: 계산 컬럼은 읽기 전용이고 수정됨 표시가 나타난다.

3. **미저장 변경 보호 (30초)**
   - 수량을 수정한 뒤 다른 문서 또는 메뉴로 이동한다.
   - “계속 편집”을 눌러 입력이 유지됨을 보이고, 필요하면 “변경사항 버리기”로 한 번만 이동됨을 설명한다.

4. **모바일 수주 (50초)**
   - 모바일 수주 화면으로 이동해 카드 조회·상세를 연다.
   - 저장한 문서를 조회하고 수량을 수정한다.
   - 기대: PC와 같은 문서번호·상세가 보인다.

5. **PDA 수주 (50초)**
   - PDA 화면에서 품목 코드 → Enter → 수량 → 단가의 연속 입력을 보인다.
   - 존재하지 않는 품목 코드를 한 번 입력해 오류 안내를 보인 뒤 정상 품목으로 복구한다.

6. **PC에서 동일 데이터 재조회 (30초)**
   - PC로 돌아와 같은 문서의 수정값을 확인한다.
   - 설명: “별도 모바일 데이터가 아니라 같은 API·Repository 경로를 사용합니다.”

7. **메일 수주 후보 (40초)**
   - 메일 수주 불러오기를 열고 정상 sample을 분석한다.
   - 후보·오류·중복 반영 차단을 간단히 설명한다.
   - 주의: 실제 메일 서버 연동이 아닌 Mock sample이다.

8. **AI 솔루션 센터와 파일 분석 (70초)**
   - TXT 또는 CSV를 첨부하고 컨설턴트 분석을 실행한다.
   - 근거, 확인 질문, 대안 비교, roadmap을 보여 준다.
   - 민감정보가 있는 sample은 가린 표시만 보이고 원문이 결과·Markdown·패키지에 남지 않는다고 설명한다.

9. **검토 기록·패키지 (35초)**
   - 역할·체크리스트로 검토 기록을 남기고 Markdown 또는 검토 패키지를 보여 준다.
   - 설명: “최종 판단은 사람이 남기며, AI가 자동 승인하지 않습니다.”

10. **자동 유지보수 근거와 한계 (35초)**
    - ANALYZE 보고의 Green/Yellow/Red와 Freeze Gate를 설명한다.
    - 운영환경 적용 전 UAT, 권한, 성능, 실제 연동 검증이 필요함을 명확히 말한다.

## 데모 중 문제 발생 시 대체 경로

- 문서 선택이 꼬이면 조회 후 첫 문서를 다시 선택한다.
- 확인 dialog가 열리면 취소로 현재 입력을 유지하고 다음 화면으로 넘어간다.
- 파일 첨부가 실패하면 사전 준비한 TXT sample로 교체한다.
- SQL Server 검증은 현장 데모에서 재실행하지 않고, 로컬 테스트 DB의 별도 실행 근거만 제시한다.
