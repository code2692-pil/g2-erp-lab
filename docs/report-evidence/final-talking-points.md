# 최종 설명 자료

## 30초 설명

수주·발주·작업지시 화면을 하나의 사용 기준으로 정리했습니다. 입력 오류와 미저장 변경을 안내하고, Grid 입력과 비동기 조회가 꼬이지 않도록 검증했습니다. AI는 자동으로 운영 코드를 바꾸는 것이 아니라, 검증 결과와 개선 후보를 사람이 판단할 수 있게 정리합니다.

## 1분 설명

PoC의 핵심은 세 화면의 실제 사용성을 맞춘 것입니다. 찾기 창, 입력 검증, 변경 보호, 저장 중 중복 클릭 방지, 마지막 조회 결과 우선 반영을 공통 기준으로 확인했습니다. Mock 50개, InMemory 18개 자동 테스트와 4개 해상도의 headed 확인으로 회귀 근거를 남겼습니다. 다만 회사 운영 코드와 SQL Server 운영 데이터에는 적용하거나 검증하지 않았습니다.

## 3분 설명의 핵심

- 시작점: 화면별로 오류·버튼·Grid 동작이 달라 재사용과 검증이 어려웠다.
- 실제 검증: 수주·발주·작업지시의 조회, 신규, 찾기 창, 입력 오류, 변경 보호, 저장, 비동기 경합을 확인했다.
- AI의 역할: 신호 수집, 위험 분류, 보고서와 후보 목록 작성이다. AI가 ERP를 완성하거나 운영 반영을 자동으로 하지 않는다.
- 회사 적용 조건: 회사 코드 diff 검토, 개발 DB 검증, 사용자 UAT, 승인된 원격 백업과 배포 절차가 별도로 필요하다.

## 도구와 사람의 역할

| 주체 | 역할 |
| --- | --- |
| GPT | 요구사항 정리와 설명 초안 보조 |
| Codex | 코드·테스트·문서 작업 보조와 근거 수집 |
| Git | 변경 이력과 검토 가능한 체크포인트 보존 |
| VS Code | 개발자가 실제 코드를 검토·수정하는 작업 공간 |
| Playwright | 브라우저 사용자 흐름의 자동 회귀 확인 |
| 사용자·컨설턴트 | 업무 규칙, 우선순위, 후보 최종 판단과 운영 적용 승인 |

## 예상 질문 답변

- **회사 코드에 바로 적용되나요?** 가능성은 검토할 수 있지만, 아직 적용·운영 검증은 하지 않았습니다.
- **AI가 자동으로 수정하나요?** 아닙니다. 현재는 ANALYZE와 보고서 중심이며 최종 결정은 사람이 합니다.
- **무엇이 검증됐나요?** PoC의 Mock·InMemory·headed 브라우저 흐름입니다.
- **무엇이 미검증인가요?** SQL Server 실제 CRUD, 고객 데이터, 고객 환경, 배포입니다.

과장하지 않는 표현: “PoC에서 검증됨”, “회사 코드 적용 가능성은 있음”, “운영 적용은 미검증”.
