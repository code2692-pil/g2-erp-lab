## 선정 결과

### 선택 후보

**초기 화면 진입용 생산 번들 분할 (87점)**

현재 생산 빌드에는 500 kB를 넘는 JavaScript 청크 경고가 남아 있다. 수주 화면은 기본 진입 화면으로 유지하고, 발주·작업지시·AI 솔루션 센터·개발 데이터·모바일/PDA 전용 화면은 사용자가 실제로 이동할 때 불러오도록 분할한다. 이는 ERP 업무 데이터, API, DTO, DB, 권한, 외부 서비스, 신규 의존성을 변경하지 않는다.

### 선택 이유

- 10개 기존 후보와 달리 회사의 업무·권한·운영 정책 결정을 기다리지 않는다.
- 현재 `App.tsx`의 화면 전환 구조와 Vite의 표준 동적 import만 재사용한다.
- 기본 수주 화면의 초기 로딩 부담을 줄이고, 화면 전환 중에는 사용자에게 접근 가능한 진행 상태를 제공한다.
- Mock 실제 UI 스모크, 생산 빌드, 정적 검사로 변경 효과와 회귀를 검증할 수 있다.

### 이번 구현 범위

- `src/App.tsx`에서 비기본 화면 모듈을 `lazy()`로 분할한다.
- 모듈을 불러오는 동안 `role="status"`와 `aria-busy`를 가진 화면 진행 상태를 표시한다.
- 기본 수주등록의 데이터 흐름과 모든 API·DTO·DB·SQL·Repository 코드는 변경하지 않는다.

### 완료 조건

1. 기본 수주등록은 기존 경로(`/`)에서 정상 표시된다.
2. 발주·작업지시·AI·개발 데이터·모바일/PDA 화면이 기존 메뉴와 직접 경로에서 정상 표시된다.
3. 생산 빌드의 기본 진입 청크가 기존 500 kB 경고 기준 아래로 분할되거나, 산출물 분할 근거가 확인된다.
4. 기존 관련 Mock Playwright UI 스모크를 변경 전·후 모두 통과한다.
5. 선택 후보와 직접 관련된 비정상/연속 전환 관찰 및 복구 확인, 단일 변이 검증 후 원상 복구가 완료된다.
6. TypeScript, 생산 빌드, .NET 솔루션 빌드, diff 검사가 통과한다.
