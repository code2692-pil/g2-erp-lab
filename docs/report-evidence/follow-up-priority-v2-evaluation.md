## 선정 후보: 상세 Grid 열 너비 조절 및 보기 설정 저장

`docs/report-evidence/erp-grid-view-preferences-summary.md`는 기존 Grid에 열 너비
조절 기능이 없음을 명시한다. 반면 `ErpDataGrid`는 이미 각 열의 `width`를 `colgroup`에
적용하고, 보기 설정은 화면별 `localStorage`에 열 표시·순서를 저장한다. 따라서 긴 품목명,
규격, 비고를 다루는 사용자가 읽기 폭을 조정할 수 있도록 하되, 업무 데이터나 서버 계약은
건드리지 않는 것이 가장 작은 안전 개선이다.

### 정확한 변경 범위

- `sales-order-lines`, `purchase-order-lines`, `work-order-lines` 상세 Grid의 기존 보기
  설정에 열 너비(px)를 선택적으로 저장한다.
- 기존 보기 설정 대화상자에 열별 숫자 입력을 추가하고, 유효 범위는 48~480px로 정규화한다.
- 저장된 너비는 기존 `ErpDataGrid`의 `colgroup`에 적용하며, 초기화하면 기본 너비로 돌아간다.
- 이전 저장 형식(너비 없음), 잘못된 저장 값, 숨김/잠금 열과 4개 PC 폭에서 안전하게 복구한다.

### 명시적 비범위

- 열 머리글 드래그 리사이즈, 계정 동기화, 업무 데이터 저장, API/DTO/Repository/DB/SQL 변경
- 수주·발주·작업지시 이외의 새 화면, 모바일/PDA, 새 의존성, 테스트 timeout/retry 조정

### 구현 전 검증 계획

1. 순수 저장·정규화·적용 로직 단위 테스트와 기존 Grid 보기 설정 E2E를 확장한다.
2. Mock과 InMemory 전체 E2E, typecheck, production build, 번들 예산, .NET build, 빠른
   Gate, 테스트 정리 검사, `git diff --check`를 실행한다.
3. 저장 너비 정규화 또는 적용 경로를 임시로 훼손해 관련 테스트가 실패하는지를 확인한 뒤 즉시
   원복하는 Mutation을 수행한다.

## 완료 조건

- 기존 열 표시/순서/키보드 흐름과 상세 Grid의 업무 데이터가 유지된다.
- 위 검증과 Mutation이 모두 PASS이고, 한 개의 로컬 체크포인트 커밋으로 확정한다.
