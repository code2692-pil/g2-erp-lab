# PC·모바일·PDA 동일 수주 데모 시나리오

## 준비

1. 로컬 API 모드를 선택한다. SQL Server 데모는 `G2ERP_DEV_LOCAL_TEST` 로컬 테스트 DB에서만 수행한다.
2. PC 수주등록 화면에서 거래처와 품목을 선택한다.
3. 데모 중에는 문서번호나 비고에 식별 가능한 테스트 표식을 사용하고, 종료 시 반드시 제품 화면에서 삭제한다.

## 동일 데이터 흐름

1. PC에서 수주를 신규 저장한다.
   - 거래처, 품목, 수량, 단가를 입력한다.
   - 저장 완료 후 발급된 문서번호를 확인한다.
2. 모바일 수주등록으로 이동한다.
   - 같은 문서번호로 조회한다.
   - 카드의 수량을 수정해 저장한다.
3. PDA 수주등록으로 이동한다.
   - 같은 문서를 조회한다.
   - 품목코드 → Enter → 수량 → Enter → 단가 → Enter 흐름 또는 행 편집으로 값을 수정해 저장한다.
4. PC로 돌아와 문서를 다시 조회한다.
   - PDA에서 바꾼 수량과 합계가 PC Grid에 동일하게 표시되는지 확인한다.
5. PDA에서 같은 문서를 삭제한다.
   - PC·모바일·PDA 각각에서 문서번호로 다시 조회해 결과가 없는지 확인한다.

## 안정성 시연 포인트

- 모바일 또는 PDA에서 A 조건으로 조회를 누른 직후 B 조건으로 다시 조회한다. B 결과만 남아야 한다.
- 조회 중 PC 또는 다른 compact 화면으로 전환한다. 이전 조회가 새 화면을 덮어쓰지 않아야 한다.
- 저장을 두 번 빠르게 누르거나 삭제를 두 번 빠르게 누른다. 첫 요청만 실행되어야 한다.
- 저장 오류가 발생하면 입력값과 `수정됨` 표시가 유지되고, 수정 없이 재시도할 수 있어야 한다.

## 반응형 확인 크기

| 구분 | 확인한 크기 |
| --- | --- |
| 모바일 | 360×800, 375×812, 390×844, 412×915 |
| PDA | 320×480, 360×640, 480×800 |

각 크기에서 조회·신규 버튼이 보이고, 문서 전체 가로 스크롤이 생기지 않는지 headed 브라우저로 확인했다.
