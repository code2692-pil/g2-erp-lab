# 모바일·PDA 수주등록 한계와 후속 검증

## 현재 PoC 범위

- 브라우저 기반 반응형 수주등록 PoC이며, 네이티브 Android·iOS 앱이나 APK가 아니다.
- 실제 PDA SDK, 바코드 스캐너, 카메라, 블루투스 프린터·장비 연동은 포함하지 않는다.
- 오프라인 저장, PWA, Service Worker, 충돌 해결 동기화는 제공하지 않는다.
- SQL Server 검증은 로컬 테스트 DB `G2ERP_DEV_LOCAL_TEST`만 대상으로 했다.
- Mock 데이터는 현재 브라우저 페이지의 메모리 PoC 상태다. 같은 화면 전환의 공통 서비스는 검증했지만, 새 탭·새로고침 뒤 영속 데이터처럼 사용하거나 실제 DB 검증으로 표현하지 않는다.

## 이번에 확인하지 않은 항목

- 실제 PDA 장비의 키 배열, 스캐너 suffix, 화면 밝기, 장갑 착용 조작성
- 저대역폭·오프라인·장시간 연결 단절 환경
- 다수 사용자가 같은 수주를 동시에 수정할 때의 업무 규칙과 낙관적 동시성 정책
- 고객·운영 DB, 운영 배포, 모바일 앱 스토어 배포
- 다른 ERP 업무 모듈과의 신규 연계
- 실제 사용자 인증·권한에 따른 화면·데이터 접근 제어

## 후속 검증 권장 순서

1. 실제 대상 PDA 또는 모바일 브라우저에서 바코드 입력·Enter 흐름과 터치 크기를 수동 확인한다.
2. 업무 담당자와 동일 문서 동시 수정 시의 우선순위·경고·재조회 규칙을 확정한다.
3. 필요성이 확정된 경우에만 오프라인 정책, 장비 SDK, 바코드 연동을 별도 관문으로 설계한다.

이번 관문은 위 후속 기능을 구현하지 않았다. 기존 수주 업무의 동일 데이터 사용과 안정적인 브라우저 흐름을 확인하는 데 범위를 한정했다.
